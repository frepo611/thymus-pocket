## Vad som gjordes

### 1. Analys av PoC-läget

Genomförde en genomgång av nuvarande status och identifierade fyra kategorier:

- **Kritiska brister**: `GetTopicAsync` returnerade alltid 0 inlägg; reply-demot körde vid varje körning och spammade forumet.
- **Viktiga**: Ingen session-persistens, ingen hantering av utgångna sessioner.
- **Bra-att-ha**: Paginering, skapa ny tråd, strukturerad felhantering.

### 2. GetTopicAsync — trasig selector fixad

**Grundorsak**: Koden letade efter `div[id^='msg_'].post_wrapper`, men den verkliga HTML-strukturen i SMF 2.1 är:

```html
<div class="windowbg" id="msg3">
  ← container (id utan underscore)
  <div class="post_wrapper">
    <div class="post">
      <div class="inner" data-msgid="3">
        ← id med underscore + data-attribut hallof
      </div>
    </div>
  </div>
</div>
```

**Fix**: Bytte till `#forumposts .windowbg` som container-selector och extraherar:

- MessageId från `data-msgid`-attributet på `.post .inner`
- Author från `.poster h4 a`
- Body från `.post .inner` (TextContent)
- Datum från `.postinfo a[rel='nofollow']` (ren text, inget `<time datetime>`-element)

### 3. Reply-demo — gated bakom config-flagga

Varje `dotnet run` postade tidigare ett riktigt svar. Åtgärdat med:

- Ny appsettings-nyckel: `Smf:EnableReplyDemo` (default `false`)
- Program.cs hoppar över demo-blocket om flaggan är falsk och skriver tydligt vad man ska ändra för att aktivera det.

### 4. Session-persistens

Lade till `SaveCookies(path)` och `TryLoadCookies(path)` på `SmfHttpClient`:

- Cookies serialiseras som JSON till `smf_session.json` (konfigurerbart via `Smf:CookieFile`).
- Vid start: om filen finns laddas cookies i cookiejar innan första anrop.
- Sparas till disk direkt efter lyckad inloggning.

### 5. Session expiry — auto-retry

Om sparade cookies är utgångna och ett anrop kastar `HttpRequestException` loggar appen "Stored session expired — re-authenticating." och gör om login automatiskt.

## Session-bugg och fix (del 2 — samma dag)

### Problem: `smf_session.json` återskapades inte efter radering

**Grundorsak**: Sökvägen var relativ (`"smf_session.json"`) och löstes mot processens _current working directory_ — vilket skiljer sig från `AppContext.BaseDirectory` beroende på hur appen startades (`dotnet run` vs direkt exe). Filen skapades alltså på inkonsekvent plats.

**Fix**: Sökvägen normaliseras nu alltid mot `AppContext.BaseDirectory`:

```csharp
var cookieFileRaw = config["Smf:CookieFile"] ?? "smf_session.json";
var cookieFile    = Path.IsPathRooted(cookieFileRaw)
    ? cookieFileRaw
    : Path.Combine(AppContext.BaseDirectory, cookieFileRaw);
```

Filen hamnar alltid i `bin/Debug/net10.0/smf_session.json` och den absoluta sökvägen skrivs ut vid varje körning.

### Problem: "Could not find SMF login form" när session laddades från disk

**Grundorsak**: Den session-validerade kodvägen anropade `LoginAsync` trots att användaren redan var inloggad. SMF visar inte inloggningsformuläret för autentiserade användare → `ExtractLoginForm` kastade undantag.

**Fix**: Lade till `GetArtifactsAsync()` som hämtar artefakter från startsidan istället för inloggningssidan. Session-vägen anropar nu den metoden:

```csharp
auth = await client.GetArtifactsAsync(); // ingen login-form behövs
```

## Ny funktionalitet: CreateTopicAsync

Lade till `CreateTopicAsync(string boardUrl, string subject, string message)` och `GetBoardUrlsAsync()` på `SmfHttpClient`. Samma GET-before-POST-mönster som `PostReplyAsync` men utan topic-parameter:

| Åtgärd        | URL                               |
| ------------- | --------------------------------- |
| Skapa svar    | `index.php?action=post;topic=X.Y` |
| Skapa ny tråd | `index.php?action=post;board=X.0` |

Båda flödena POSTar till `action=post2` med samma CSRF-fält. Ny config-nyckel: `Smf:EnableCreateTopicDemo`.

## Forumets HTML-struktur — samlad referens

Dokumenterat från faktisk inspektion av `http://smf.local:88` (SMF 2.1.0, Docker + MySQL).

### Routing / dispatcher

Alla anrop går till `index.php`. Parametrar styr vad PHP-dispaatchern gör:

| Parameter                   | Exempel                            | Vad som visas            |
| --------------------------- | ---------------------------------- | ------------------------ |
| `action=login`              | `/index.php?action=login`          | Inloggningsformulär      |
| `action=login2`             | _(POST-mål)_                       | Behandlar inloggning     |
| `action=post` + `board=X.0` | `/index.php?action=post;board=1.0` | Formulär för ny tråd     |
| `action=post` + `topic=X.Y` | `/index.php?action=post;topic=3.0` | Formulär för svar        |
| `action=post2`              | _(POST-mål)_                       | Behandlar tråd/svar      |
| `action=unread`             | `/index.php?action=unread`         | Olästa inlägg            |
| `action=recent`             | `/index.php?action=recent`         | Senaste inlägg           |
| `board=X.0`                 | `/index.php?board=1.0`             | Trådlista för ett board  |
| `topic=X.Y`                 | `/index.php?topic=3.0`             | Tråd med inlägg          |
| _(inget)_                   | `/index.php`                       | Startsida med boardlista |

SMF använder semikolon (`;`) som separator i query string (inte `&`) för action + topic/board-kombinationer.

**Okänd action → 404. Inget action → startsida/boardindex.**

### CSRF — varje POST kräver dynamiska dolda fält

Varje formulär innehåller två dolda fält som varierar per session:

```html
<input type="hidden" name="b628625c" value="8d56f04a427500ceeac5a15d589dade1" />
<input type="hidden" name="sc" value="..." />
```

- Fältnamnet (`b628625c`) är `session_var` — en slumpmässig nyckel per PHP-session.
- Värdet (`8d56f04a...`) är `session_id`.
- Båda finns som JavaScript-globaler i varje sida: `var smf_session_var = '...'; var smf_session_id = '...';`
- **Obs**: Denna PoC har ingen `sc`-token (se copilot-instructions.md) — `sc`-fältet ignoreras.

### Cookies

| Cookie         | Beskrivning                                                                                                                             |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `SMFCookie956` | Huvud-login-cookie. Värdet är URL-enkodad JSON med nycklarna `"0"`–`"4"`: user_id, lösenordshash, utgångstid, tom sträng, sökväg (`/`). |
| `PHPSESSID`    | PHP-sessionskaka. Vanlig 26-teckens sträng.                                                                                             |
| _(TFA-cookie)_ | Saknas i denna installation.                                                                                                            |

Cookie-namn innehåller portnumret: `SMFCookie956` (port 88 → suffix 956 beräknat från `88 * 11 - 12` eller liknande intern formel).

### Startsidan — boardlista

```html
<a class="subject" href="index.php?board=1.0">General Discussion</a>
```

Selector: `a.subject[href*='board=']`

### Trådlista på board-sida

Två olika layouter förekommer:

**Kompakt (senaste/olästa):**

```html
<tr>
  <td class="subject"><a href="...topic=3.0">MONGOS TRÅD</a></td>
</tr>
```

Selector: `tr td.subject a[href*='topic=']`

**Board-sida (kort/windowbg-kort):**

```html
<div class="windowbg ...">
  <div class="message_index_title">
    <span id="msg_42">
      <a href="index.php?topic=3.0">MONGOS TRÅD</a>
    </span>
  </div>
</div>
```

Selector: `#topic_container > .windowbg .message_index_title span[id^='msg_'] a[href*='topic=']`

**Viktigt**: `id^='msg_'` (med underscore) på `<span>`, men `id^='msg'` (utan underscore) på `<div>`-containers i trådsidan. Inkonsekvent namngivning i SMF.

### Tråd-sida — inlägg

```html
<div id="forumposts">
  <div class="windowbg" id="msg3">
    <!-- id utan underscore -->
    <div class="post_wrapper">
      <div class="poster">
        <h4><a href="...">mongo</a></h4>
      </div>
      <div class="postinfo">
        <a rel="nofollow">May 25, 2026, 12:45:22 PM</a>
        <!-- datum som ren text -->
      </div>
      <div class="post">
        <div class="inner" data-msgid="3">
          <!-- id med underscore i data-attr -->
          hallof
        </div>
      </div>
    </div>
  </div>
</div>
```

Selektorer:

- Container: `#forumposts .windowbg`
- MessageId: `data-msgid` på `.post .inner`
- Författare: `.poster h4 a` (TextContent)
- Brödtext: `.post .inner` (TextContent)
- Datum: `.postinfo a[rel='nofollow']` (TextContent, parsas med `DateTimeOffset.TryParse`)

**Obs**: Inga `<time datetime="...">` element — datum finns bara som formaterad text.

### Formulärstruktur (login, svar, ny tråd)

Alla formulär identifieras via action-URL:

```html
<form action="index.php?action=login2;...">
  <input type="hidden" name="b628625c" value="8d56f04a..." />
  <input type="text" name="user" />
  <input type="password" name="passwrd" />
</form>
```

`ExtractFormFields(html, "login2")` hittar formuläret på `action`-attribut som innehåller `action=login2` (case-insensitive).
